# 進行台本

高校生向けプログラミング体験授業「Webページから情報を取り出してみよう」の進行台本。

- 対象：プログラミング未経験の高校生（想定20名）
- 所要：**計89分**（**どこで区切るかは講師が決める**。時間が足りない回・余った回は「時間調整」の項を参照）
- 使うもの：Google Colaboratory、`notebooks/student.ipynb`、`docs/slides.md`（投影）、`docs/handout.md`（配布）
- 対象サイト：https://yuracode.github.io/isshop/ （授業用に自前で用意した架空の購買部・30商品）

### 教材の使い分け

| 教材 | だれが見るか | 役割 |
|---|---|---|
| `docs/slides.md` | 全員（投影） | 話の骨格。**説明はここで完結させる** |
| `docs/handout.md` | 生徒（配布） | 手元の早見表。タグ・命令・エラー対処 |
| `notebooks/student.ipynb` | 生徒（Colab） | 手を動かす場所 |
| `docs/lesson-plan.md` | 講師 | この台本 |

スライドとプリントは**内容が重なっている**。これは意図的で、
投影を見逃した生徒が手元で追いつけるようにしてある。
**「プリントに載ってるから、覚えなくていい」と最初に言い切ること。**

## 2. 各ステップで言うこと

### 導入（5分）

> 「ネットのページって、みんな目で見て読んでるよね。今日はそれをプログラムに読ませます。
> 20分後には、30個の商品の名前と値段が一瞬でずらっと並びます。」

- ゴールを先に見せる。可能なら講師画面でステップ3の完成形を1回実行してみせる。
- 「今日は文法は覚えなくていい。動かすことだけやります」と明言する。

**Colab を開かせる**

1. `student.ipynb` を配布（Google Drive 共有 or GitHub リンク）
2. Colab で開く → **Google アカウントのログインが必要**
3. 「ドライブにコピー」を押させる（コピーしないと保存できない）

### 第1部：HTML の話（8分）

**スライド5〜21。ここは講師が話す時間で、生徒は手を動かさない。**
プログラミング未経験どころか HTML も初めて、という前提で組んである。

> 「みんながいつも見ているWebページ。あれ、コンピュータの中では
>  **ぜんぶ文字で書かれた設計図**なんです。ブラウザはそれを読んで絵にしてる。」

押さえるのは次の5点だけ。**網羅しようとしないこと。**

| 話すこと | 到達点 |
|---|---|
| タグ | `< >` で囲む、閉じるほうに `/` が付く、中にタグが入る |
| `<title>` と `<h1>` の違い | タブに出る名前 / ページの中の見出し。**ステップ1の伏線** |
| `<div>` は箱 | 商品1つ分 = `<div>` 1つ。まとめるための入れもの |
| `<span>` | 文の一部を囲む。だから「150」だけを狙える |
| class は名札 | 同じ `<h2>` を区別するために付いている |

- **スライド18「商品1つ分の中身」がこの部の山**。ここだけは全員の顔を上げさせる。
  プリントの6章に同じ図があるので、手元と投影の両方を見せる。
- 「なぜ150と円が分けてあるか」（スライド20）は、ステップ3の `int()` の伏線。
  ここで種を蒔いておくと、あとで「あ、さっきの」となる。
- **タグの一覧を暗記させない。** 「プリントに載ってるから見ていい」と明言する。

### ステップ0：相手を見る（3分）

> 「コードを書く前に、まず相手を見ます。プログラムに読ませたいページを、
> 自分の目で先に見ておく。これは今日いちばん大事な順番です。」

- ブラウザで対象サイトを開かせ、5つのカテゴリに30商品あることを確認させる。
  **「これを手で書き写す気になる？」**と聞くと、このあとのループの動機になる。
- 余裕があれば右クリック →「検証」で HTML を見せる。
  同じ形の `<div class="item">` がくり返しならんでいることだけ指させれば十分。
  **タグの文法説明には入らない。** 「文字で書いてあるんだな」で終わらせる。

### ステップ1：タイトルを取る（10分）

> 「やることは2つだけ。ページを取ってくる。その中からタイトルを探す。以上です。」

- 準備セルを実行させ、**全員の画面に「準備できました」が出たことを目視で確認する。**
  ここを飛ばすと以降すべてエラーになる。教室を1周する価値がある。
- `print(html[:300])` の出力を見せて「記号だらけで読めないよね」と共感してから
  `BeautifulSoup` に渡す。**分解する係を雇った**、というイメージで説明する。
- `soup.title` と `soup.title.text` の差をその場で実演する（タグごと / 中身だけ）。

> 「取れた人？」と挙手させる。**今日最初の成功体験なので、必ず声に出させる。**

### ステップ2：商品名を全部ならべる（12分）

> 「1個取れたら、あとは同じことを30回くり返すだけです。
> でも30回コピペするのは嫌だよね。だから `find_all` とループを使います。」

- `find` は最初の1つだけ、`find_all` は全部。**ここは板書する。**
- `print(len(items))` で `30` が出た時点で一度止める。数が合えば以降は必ず成功する。
  ページ上部にも「ぜんぶで30商品」と書いてあるので、突きあわせて確認させる。
- 30行ずらっと出た瞬間がいちばん盛り上がる。手を止めて隣同士で画面を見せ合わせる。

### ステップ3：最安値を探す（12分）

> 「名前が取れたら、値段も同じやり方で取れます。class の名前を変えるだけ。」

- `item-name` → `item-price` に変えるだけで動く、という**再利用の感覚**を強調する。
- `int()` の必要性は、`print(price_text + 10)` を実演してエラーを見せるのが一番早い。
- ノートブックの 3-1 に `# print(price * 2)` をコメントで置いてある。**外すと `150150`。**
  「2個分の値段のつもりが、ただ2回くり返っただけ」。エラーより先にこれを見せると、
  文字と数の違いが**エラーなしで**伝わる。

> 「見た目は同じ150でも、コンピュータにとっては『文字の150』と『数の150』は別物です。
> 文字だと足し算できない。だから `int` で数に変えます。」

- 最安値ループは、**先に日本語で手順を言ってからコードを見せる**。
- 答えは「クリアファイル 80円」。30個を目で探すと手間だが、コードなら一瞬という対比を見せる。
- 早く終わった生徒には「やってみよう（もうひとつ）」でカテゴリも取らせる。
  `item-name` → `item-category` に変えるだけで動く、という再利用の感覚をもう一度踏ませる。

> 「上から順に見ていって、いままでで一番安いやつより安かったら、覚えなおす。
> 最後まで見たら、覚えているのが最安値。やってることはこれだけです。」

### ステップ4：ほしいものだけ選ぶ（10分）

> 「30個ぜんぶ出せるようになりました。でも、30個ならんでも選べないよね。
>  ここからは**取ったあとの話**です。選ぶ、ならべかえる。」

- `if` は「**もし〜なら**」の一言で済ませる。`=` と `==` の違いは聞かれたら答える程度に。
- 空欄は `<=`。**「以下は `<=`、未満は `<`」**だけ板書する。プリント7章にも載っている。
- `4-2` の `prices.append((price, name))` は写経でよい。
  **「値段を先に書くと、値段の順にならぶ」**ことだけ伝われば十分。
- 90円が2つ（使い捨てカイロ・消しゴム）ある。同じ値段のときは名前の順になる。
  聞かれたら「値段が同じなら名前で決めてる」で十分。
- 早い生徒には `prices.sort(reverse=True)` で高い順を試させる。

### ステップ5：カテゴリごとに数える（8分）

> 「パンって平均いくらだと思う？ 飲み物は？ ……数えてみましょう。」

- **今日いちばん新しい文法（辞書）が出る場所。説明しきろうとしないこと。**
  「名前で覚えておく入れもの」「`get(cat, 0)` は無ければ0から」で止める。
- 空欄は `item-category`。プリント6章の class 表にある。
- `5-2` の結果は パン182 / 軽食162 / 飲み物118 / 文具113 / **日用品285**。
  ここで必ず一度止めて、**「日用品って、そんなに高い？」**と問いかける。
- `5-3` はステップ4の `append` と `sort()` の使い回し。**新しい文法は無い**と先に言うと手が止まらない。
  安い順に **90 / 110 / 150 / 180 / 200 / 980** と並び、980 が最後に浮いて見える。
- `5-3` で中身を見ると、980円の折りたたみ傘が1本混ざっている。**ここが今日の山。**

> 「平均が高いから日用品は高い、って言っていい？ 中身を見たら、傘が1本混ざってただけでした。
>  数字が出てきたら、中身を見にいく。これはプログラムの話じゃなくて、データの話です。」

- 時間が押していたら `5-1` `5-2` は講師画面で見せ、`5-3` だけ手を動かさせる。

### ステップ6：詳細ページを辿る（8分）

> 「一覧ページには在庫が書いてありません。在庫は商品ごとのページにあります。
> だからリンクをたどります。……といっても、やることはステップ1と同じです。」

- **新しいことは何もしていない**と言い切ってよい（取ってくる → 分解する → 探す）。
- `items[:5]` で**先頭5商品だけ**にしてある。**5秒待たされる体感が、次のマナーの話の入口**。
  `[:5]` はステップ4の `prices[:5]` と同じ書き方。**新しいことは何もしていない。**
  待っているあいだに黙らず、「いま1個ずつ、向こうに聞きにいってます」と実況する。
- 「`[:5]` を外して30商品ぜんぶにしたら何秒かかる？」と口頭で問う（30秒）。
  **実際には流させない。** 30倍の時間がかかる＝相手に30倍お願いしている、という換算を口で言う。

### マナーの話（5分）

→ 第4章に台本あり。**ステップ6の直後にやる。**

### ステップ7：本物の Wikipedia 記事（15分・発展）

> 「ここまでは、先生がみんなのために用意したページでした。
>  class に `item` とか `item-price` とか、わざわざ名前が付けてありましたよね。
>  最後は本物です。本物には、そんな親切はありません。」

**読みこむのは保存版であることを、必ず最初に言う。**

> 「本物の Wikipedia を20人で一斉に叩くんじゃなくて、先生が前もって**1回だけ**取ってきて、
>  さっきの購買部と同じ場所に置いてあります。さっきのマナーの話、そういうことです。」

- ブラウザで本物の記事を開くのは自由だと明言する。**人が読むのは普通の閲覧**。
  「機械に何回もやらせる」ことだけが別の話、という線引きをここで引く。

**7-2（`id`）** — class との違いは1行で済ませる。

> 「class は**同じ仲間が何個もある**印。id は**ページに1個しかない**印。
>  さっき商品が30個ぜんぶ `class="item"` だったでしょ。あれが class。」

**7-3（見出し）** — 1行目に「目次」が混ざる。**ここは笑いどころにしてよい。**

> 「ほら、いらないものが入ってる。本物ってこうです。
>  ほしいものだけ並べておいてくれる親切なページは、世の中にはあまりありません。」

**7-4（脚注の掃除）** — このステップの山。

> 「取れたけど、`[1]` `[2]` がじゃまだよね。**取ったあとに掃除する**。
>  本物のスクレイピングは、じつはこの掃除のほうが仕事の量としては多いです。」

- 最後の一文「多くのメロンパンにはメロンが入っていない」で場がなごむ。ここで切ってよい。

**7-5（API・講師機で1回だけ）** — 時間があれば。

- **生徒には実行させない。講師画面で見せる。**
- 7-4 で掃除した文章が、掃除なしで返ってくることを見せる。
- 続けて**この学校の記事**を同じやりかたで取る。記事名を変えただけで取れることを見せる。

> 「Wikipedia は、そもそも『データがほしい人はこっちからどうぞ』という入口を用意しています。
>  こっちを使ったほうが速いし、相手のコンピュータにもやさしい。
>  さっきの掃除、そもそも要らなかったんです。」

- `User-Agent` の行を指させる。**`headers` を消すと本当に 403 が返る**（確認済み）ので、
  余裕があればその場で1回だけ実演する。

> 「名乗ってないと、入れてもらえません。『どこの誰が何のために来たのか』を言う。
>  人間の世界と同じです。」

**7-6（RSS・講師機で1回だけ）** — 7-5 とセットで。**入口は API だけではない**、の2例目。

- **生徒には実行させない。講師画面で見せる。**

> 「ニュースのサイトも、見出しを配るための入口を出しています。
>  トップページを開いて、どこに見出しがあるか探して、むしって……をやらなくても、
>  こっちに聞けば見出しだけが並んで返ってきます。
>  さがすのは『どこをむしるか』より先に、『入口があるかどうか』です。」

- **UA を偽装していないこと**を画面で指させる。7-5 で「名乗れ」と言った直後に
  ブラウザのふりをするコードを見せると、話がそのまま逆になる。
- **見出しの中身は選べない。授業直前に1回実行して、何が出るか見てから投影する。**
- 出なければ粘らない。口頭に切り替えてよい。伝えたいのは結論のほうで、実行結果ではない。

### まとめ（5分）

> 「今日やったのは3つだけ。取ってくる、分解する、探す。
> 相手のサイトが変わっても、やることは同じです。
> 違うのは『どの class を指定するか』だけ。」

- 「自分だったら何を取りたい？」を1人1つ言わせると、次につながる。
- ステップ7まで行った回では、**「相手が入口を用意しているなら、そっちを使う」**を
  最後にもう一度言う。今日いちばん持ち帰ってほしい判断基準はここ。

## 3. つまずきポイントと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| ノートブックが開けない / 保存できない | Google アカウント未ログイン、ドライブにコピーしていない | 冒頭で「ドライブにコピー」を全員に押させる。学校アカウントで Colab が制限されていないか**前日までに必ず実機確認する** |
| `NameError: name 'requests' is not defined` | 準備セルを実行していない | 「上から順に、飛ばさず実行」を徹底。セル左の実行済みマーク（`[1]` などの数字）を見る習慣をつけさせる |
| `NameError: name 'soup' is not defined` | 途中のセルを飛ばした | 同上。ランタイムを再起動した場合も同じ症状になる |
| `IndentationError: unexpected indent` | **全角スペースの混入**、または字下げのずれ | 日本語入力のまま打つと起きる。「`for` の下の行は半角スペース4つ」と板書。直せない生徒には該当行を消して打ち直させる |
| `AttributeError: 'NoneType' object has no attribute 'text'` | class 名のつづり間違い（見つからず `None` が返っている） | いちばん多いエラー。「`None` は『見つからなかった』の意味」とだけ伝え、class 名を1文字ずつ照合させる |
| `find_all` したのに1つしか出ない / ループが回らない | `find` と `find_all` の混同 | `find`＝最初の1つ、`find_all`＝全部。`print(len(items))` で個数を確認する癖をつけさせる |
| `TypeError: can only concatenate str (not "int") to str` | `int()` をかけずに計算しようとした | ステップ3-2 に戻る。むしろ狙って見せてよいエラー |
| 日本語が `ã¡ã­ã³ãã³` のように化ける | `res.encoding = "utf-8"` の行を消した／打ち間違えた | その行を復活させる。理屈は「日本語の読み方を指定している」で流してよい |
| `totals.get(cat, 0)` が理解できない | 辞書が初出 | **理解させようとしない。**「名前で覚えておく入れもの」「無ければ0から」で止め、写経でよいと言い切る |
| Wi-Fi が不安定でページが取れない | 回線 | 再実行させる。復旧しない場合は講師画面で進め、写経ではなく**見せる**に切り替える |

## 4. スクレイピングのマナー（5分の台本）

**禁止事項を並べる時間にしない。「なぜそうするのか」が分かる形で話す。**

### 話の順番

**(1) さっきの5秒を思い出させる**

> 「ステップ4で、5個の商品を見にいくのに5秒かかったよね。
> あれは、わざと1秒ずつ待つように書いてあります。なぜだと思う？」

> **ステップ4を省略した回は、代わりにこう入る。**
> 「みんな、さっき1回だけページを取りにいったよね。あれ、一瞬だったでしょ。
>  じゃあ、あれを30回、300回、待たずに連続でやったらどうなると思う？」
> （`time.sleep(1)` の行をスライドで見せるだけでもよい）

**(2) 相手側の視点に立たせる**

> 「みんながさっき叩いていたページは、どこかのコンピュータが動いて返してくれています。
> 1回のアクセスはたいしたことない。でも、待たずに30回、300回、3000回だったら？
> しかもこの教室には20人います。20人 × 3000回 が一斉に来たら、そのコンピュータはどうなる？」

- 「攻撃するつもりがなくても、結果として攻撃になる」ことを腹落ちさせる。
- **今日わざわざ自前の練習用サイトを用意した理由**もここで明かす。
  「よそのお店のサイトで練習したら、それだけで迷惑になるから」。

**(3) 3つの目安を渡す**

| 見るもの | 何が書いてあるか |
|---|---|
| 利用規約 | 「自動でデータを集めてはいけない」と書いてあるサイトがある。**書いてあったら従う** |
| robots.txt | サイトの入口に置いてある、機械向けの「入っていい／だめ」の案内板。`https://例.com/robots.txt` で見られる |
| 間隔 | 1回ごとに1秒あける。急ぐ理由はたいていない |

- robots.txt は実際に1つ開いて見せると早い（**アクセスは講師機から1回だけ**）。
  `https://news.yahoo.co.jp/robots.txt` は、冒頭に `Disallow: /`（全部だめ）を
  名指しされた機械の名前がずらりと並んでいる。**名乗った名前で扱いが変わる**のが目で見える。

> 「名前で断られてるでしょ。だから名乗るんです。
>  名乗らない機械は、そもそも信用してもらえません。」

**(4) 技術の使い方の話として閉じる**

> 「同じコードが、便利な道具にも迷惑にもなります。分けているのは技術じゃなくて、使い方です。
> 今日みんなが書いたコードは、あと1文字変えるだけで、よそのサイトに向けられます。
> できるようになった、というのはそういうことです。」

- 説教で終わらせない。「相手がいることを想像できるかどうか」に着地させる。

### この時間で**言わない**こと

- 法律の細かい話（著作権法、不正アクセス禁止法の条文）。中身が伝わらないまま怖がらせるだけになる。
- 「絶対にやってはいけない」という言い切り。判断できる材料を渡すのが目的。

## 5. 想定質問と回答例

**Q. これって悪いことなんですか？**
> 道具そのものは中立です。検索エンジンも同じことをしています。
> 問題になるのは「相手に迷惑をかける使い方」と「使ってはいけないと言われている場所で使うこと」。
> だから今日は、迷惑にならない自前のサイトを用意しました。

**Q. Amazon とか楽天でもできますか？**
> 技術的にはできます。でも多くのサイトは利用規約で禁止しています。
> それに、大きいサイトは自動アクセスを見分けて弾く仕組みを持っています。
> 「できるか」と「やっていいか」は別の質問です。

**Q. ニュースサイトの見出しは取れますか？**
> 取れます。ただしトップページの HTML を直接むしるのは筋がよくありません。
> 見た目は予告なく変わるので、今日動いたコードが明日は動きません。
> ニュースサイトの多くは **RSS** という配信用の入口を出していて、
> そこには見出しが、機械の読む形でそのまま並んでいます。
> 「どこをむしるか」より先に、「入口が用意されていないか」をさがしてください。
（※講師機で見せるなら `instructor.ipynb` の 7-6。**生徒には実行させない**）

**Q. `class_` のアンダースコアは何ですか？**
> Python では `class` という言葉が別の意味で予約されているので、
> かぶらないように `_` を付ける決まりになっています。おまじないだと思ってください。
（※深追いされたら「クラスという別の機能がある」とだけ。オブジェクト指向の説明には入らない）

**Q. `html.parser` って何ですか？**
> 「どのやり方で分解するか」の指定です。他のやり方もありますが、
> 今日はこれで十分なので、そう書くものだと思ってください。

**Q. 覚えないといけないことが多すぎます**
> 今日覚えるのは3つだけです。取ってくる、分解する、探す。
> 書き方は毎回調べればいい。プロも調べながら書いています。

**Q. 画像は取れますか？**
> 取れます。`<img>` というタグを探して、その `src`（画像の場所）を取り出します。
> やり方はステップ4のリンクとまったく同じです。

**Q. ログインが必要なページは？**
> できなくはないですが、ぐっと難しくなりますし、規約で禁止されていることが多いです。
> 今日の範囲を超えるので、興味があったら調べてみてください。

**Q. Wikipedia はスクレイピングしていいんですか？**
> 条件つきでいい、が正確なところです。Wikipedia の robots.txt には
> 「行儀のいい、速度の遅いプログラムなら記事ページを見にきて構わない」と書いてあります。
> ただし「どこの誰が出しているリクエストか名乗ること」が求められていて、
> 名乗らないと弾かれます。実際、名乗らずにアクセスすると `403`（お断り）が返ってきます。
> 今日みんなが読んだのは、先生が前もって1回だけ取ってきて置いた保存版です。
（※「20人程度のアクセスは Wikipedia には全然たいした量ではない」というのは事実。
　 聞かれたらごまかさずそう答えたうえで、**学校からは全員が同じ1つの住所に見える**こと、
　 記事は毎日書きかわるので授業中に壊れうること、を理由として挙げる）

**Q. 家でもできますか？**
> できます。Colab はブラウザだけで動くので、家のパソコンでも同じノートブックが開けます。
> ただし練習は今日のサイトで。よそのサイトはさっきの話を思い出してください。
> どうしても本物を触りたいなら、RSS のように**相手が配るために出している入口**からどうぞ。
